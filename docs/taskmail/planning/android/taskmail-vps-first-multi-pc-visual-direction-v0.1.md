# TaskMail VPS-First 多 PC 高保真视觉方向（v0.1）

更新时间：2026-03-25

## 状态

本文是 `VPS-first 多 PC` 主线下，Android 侧高保真视觉方向的 companion doc。

它依附于以下文档：

- `docs/taskmail/planning/android/taskmail-vps-first-multi-pc-user-requirements-authority-v0.1.md`
- `docs/taskmail/planning/android/taskmail-vps-first-multi-pc-information-architecture-v0.1.md`
- `docs/taskmail/planning/android/taskmail-vps-first-multi-pc-core-screen-low-fi-v0.1.md`

它不承担当前实现 truth，也不替代最终组件库、设计 token 或具体 Compose 实现。

本文回答的问题是：

**在低保真结构已经确定后，TaskMail 这条 `VPS-first` 主线的高保真视觉气质、信息层级和交互感应朝什么方向收敛。**

## 目标

本文只冻结以下几类内容：

1. 产品整体视觉气质
2. 三张核心页面的层级重点
3. 状态、结果、文件、执行策略的视觉优先级
4. 不应走向的 UI 方向

## 一句话视觉方向

TaskMail 的目标不是做成：

- mail 收件箱
- 聊天玩具
- 节点监控台

它应当更像一个：

**面向移动端的轻量工作台。**

关键词应固定为：

- 克制
- 清晰
- 可持续阅读
- 强状态感
- 弱协议感

## 总体视觉基调

### 应有的感觉

- 像一个“我可以长期盯着工作进度”的工具
- 能清楚区分“需要我行动”和“系统正在自己跑”
- 既有工作台的组织感，又不压成企业后台控制台

### 不应有的感觉

- 不要像 Gmail / Outlook 的邮件列表
- 不要像即时聊天 app 的连续气泡
- 不要像调试终端或日志面板占满整个主界面
- 不要把协议对象和字段名变成主视觉语言

## 信息层级原则

高保真设计必须把信息层级固定成下面这套顺序：

1. 我现在最该关注什么
2. 这条任务当前是什么状态
3. 它正在做什么
4. 它最终给了我什么
5. 相关设置和底层细节是什么

翻译成 UI：

- 首页优先级：`需要我处理 > 进行中 > 最近结束 > PC/workspace`
- Session 页优先级：`状态 > follow-up 可操作性 > 过程直播 > 结果 > 文件 > 细节`
- 新任务页优先级：`任务输入 > 路由选择 > 高级执行设置`

## 首页视觉方向

### 目标感受

首页应像“工作台总览”，不是“收件箱”。

用户一眼应先看到：

- 哪些 session 需要我处理
- 哪些 session 正在运行
- 我可以从哪里开始一个新任务

### 建议视觉结构

- 顶部保留一个清晰但不厚重的 app bar
- `新建任务` 作为高权重主按钮
- `需要我处理` 区使用最强视觉强调
- `进行中` 区次一级
- `最近结束` 区弱于前两者，但比 `PC/workspace` 更重要
- `PC` 与 `workspace` 区块做成辅助导航信息，不喧宾夺主

### 首页卡片风格建议

- `session` 卡片比 `PC` 卡片更大、更有信息密度
- `需要我处理` 的 session 卡片应具有明显强调色或形态差异
- `PC` 卡片应更轻量，承担环境上下文，不抢主线

## 新任务页视觉方向

### 目标感受

新任务页要让用户进入“开始一项工作”的状态，而不是“配置一个系统任务”。

### 视觉重点

- 任务输入区必须是主视觉焦点
- `PC` / `workspace` 选择器要清楚，但不应压过输入框
- 高级执行设置应弱化为可展开区域

### 执行策略的视觉读法

`backend / profile / permission` 应统一被读成“这次怎么跑”。

所以视觉上：

- 它们应放进高级区或次级区
- 默认不占据首屏大面积空间
- 展开后也应保持清晰、简洁，不做成技术表格

### 不应采用的样式

- 不要把 `profile / permission` 做成设置页式大表单
- 不要默认展示 raw model id
- 不要把 `backend_transport` 做成主选择项

## Session 页视觉方向

### 目标感受

Session 页应是“工作现场”，不是“消息对话页”。

用户进入后，应迅速理解：

- 它现在处于什么阶段
- 是否需要我马上行动
- 系统刚刚做了什么
- 目前有没有结果和文件

### 视觉主次顺序

Session 页建议固定为：

1. Header identity
2. 状态卡
3. 最近上下文摘要
4. Follow-up 可操作性
5. 过程直播
6. 结果卡
7. 文件区
8. 细节 / 设置 / 历史层

### 状态卡的视觉要求

状态卡应有很强的“现在态”感。

具体要求：

- `awaiting_user_input` 必须最醒目
- `running` 应让用户感到系统正在推进
- `done` 要稳定、收口、可放心离开
- `failed` 要清楚但不制造混乱

### 最近上下文摘要的视觉要求

最近上下文摘要不是完整聊天记录。

它应做到：

- 让用户快速找回上一轮
- 明确指出最近一次结论
- 如果当前在等用户，直接说明在等什么
- 给出清楚的 `查看前续 / 历史上下文` 入口

它的视觉权重应低于状态卡，但高于长直播。

### 直播区的视觉要求

直播区不是聊天气泡区。

建议方向：

- 更接近结构化日志流
- 但比终端日志更友好
- assistant/system/stderr 明确分层
- 长内容支持折叠和回放，但默认不压过状态和结果

### 历史上下文层的视觉要求

历史上下文层应像“回合档案”，不是无限长滚动聊天页。

建议方向：

- 按回合卡片组织
- 最新回合默认展开
- 更早回合折叠
- 需要时再进入完整过程明细

### 结果区的视觉要求

结果区必须有“结论已经落地”的感觉。

建议强调：

- final status
- summary
- 关键 structured highlights
- 实际生效的执行策略

结果区应明显区别于直播区，避免用户把过程文本误读成最终结论。

### 文件区的视觉要求

文件区应像“结果附件区”，而不是调试附件列表。

文件项建议包含：

- 文件名
- 类型 / 大小
- 查看或下载动作

并明确与结果区相邻，而不是埋到页面底部的技术细节区。

## 执行策略的视觉表现

`execution_policy` 的视觉处理应满足：

- 创建时是高级设置
- 运行中是轻量摘要
- 结束后是审计回显

具体表现建议：

- 新任务页：折叠面板
- Session 页运行中：一行摘要
- 结果页：`effective execution` 小卡片

它不应被做成：

- 全局设置中心
- 权限管理面板
- 多层专家模式菜单

## 状态色与语义色方向

当前先冻结语义层，不冻结具体色值。

建议保持以下语义稳定：

- `需要我处理`：最高提醒层
- `运行中`：进行中层
- `成功/完成`：稳定收口层
- `失败`：异常层
- `离线/stale`：环境可用性层

注意：

- `permission=highest` 不应借用危险色
- 它是执行档位，不是越权行为警告

## 动效方向

动效只应服务于状态理解，不应服务于炫技。

建议方向：

- 首页 section 刷新用轻量过渡
- Session 页新输出到达时做温和追加提示
- 状态变化时做明确但短促的转场
- `awaiting_user_input` 可有轻微强调动效

不建议：

- 大面积弹跳
- 聊天气泡式密集入场动画
- 长时间 skeleton 占据主工作区

## 空状态与异常状态的视觉方向

### 空状态

空状态应把用户带回主动作：

- 没有 session -> 引导新建任务
- 没有可用 PC -> 提示环境不可用

### 异常状态

异常状态应回答：

- 什么失败了
- 失败影响的是哪一层
- 用户下一步能做什么

所以错误卡应优先给：

- 用户可理解原因
- 推荐动作
- 是否可以重试

而不是先暴露内部 error code。

## 文案方向

文案应优先使用任务语义和用户语言：

- 新建任务
- 继续这条任务
- 查看状态
- 需要你的回复
- 已完成
- 失败

技术语义应退居辅助层：

- session id
- resolved model
- machine-readable error code

## 平台感与个人感

因为这条主线是 `VPS-first` 多 PC 工作台，视觉上要兼顾两种感觉：

- 有平台级组织能力
- 又仍是个人工作工具

所以应避免做成：

- 过重的企业后台
- 过轻的聊天玩具

更好的方向是：

- 稳定的卡片式工作台
- 清晰的层次
- 较低噪声
- 让长时间使用不累

## 视觉 guardrails

后续做高保真或组件设计时，若出现以下情况，应判定为偏离当前主线：

- 首页重新长成 mail inbox
- Session 页主要由聊天气泡组成
- `PC` 卡片比 `session` 卡片更抢眼
- 直播区比结果区更像主结论区
- `profile / permission` 被做成主导航对象
- 页面主文案大面积使用协议字段名

## 与后续设计的关系

本文冻结的是视觉方向，不是最终像素稿。

后续若继续推进，下一层设计应收敛到：

- 组件级 layout 规则
- design token
- 页面级高保真稿
- Compose 组件与状态实现
